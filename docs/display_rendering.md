# Display Rendering: FrameBuffer, EPD_Landscape and Writer

Explains how drawing pixels, rendering text and pushing to the physical display
fit together in HAUKI.

## Three-layer model

```text
Application code
      │  calls Writer.printstring() / FrameBuffer primitives
      ▼
FrameBuffer  (in-memory pixel buffer owned by EPD_Landscape)
      │  buffer flushed by EPD_Landscape.display()
      ▼
EPD_Landscape  (transposes buffer, sends over SPI)
      │
      ▼
Physical e-ink panel
```

No pixel reaches the screen until `display()` is called. Drawing methods
only mutate bytes in RAM.

---

## FrameBuffer

`EPD_Landscape` inherits from `framebuf.FrameBuffer`. The FrameBuffer is
initialised in `__init__` with:

```python
super().__init__(self.buffer, self.width, self.height, framebuf.MONO_VLSB)
```

- `self.buffer` — a `bytearray` allocated by `EPD_Landscape` (not by FrameBuffer).
- `self.width = 250`, `self.height = 122` — landscape dimensions.
- `framebuf.MONO_VLSB` — monochrome, vertical bytes, LSB at top.

### MONO_VLSB memory layout

Each byte encodes a vertical strip of 8 pixels. Bit 0 (LSB) is the top pixel;
bit 7 (MSB) is the bottom pixel of that strip.

```text
Byte at offset n covers pixels:
  x = n % (width / 8? no — n % width_in_bytes... actually:)

  x = n // (height / 8)     [column group]
  y_base = (n % (height_bytes)) * 8   [row group]

  pixel (x, y_base + bit) is set if byte & (1 << bit)
```

More concretely: for `width=250`, `height=122`, height rounds up to 128 (16
bytes per column). Bytes are laid out column-major: all bytes for column 0
first, then column 1, etc.

### FrameBuffer drawing primitives

All primitives write to `self.buffer` in-place:

| Method | Description |
|--------|-------------|
| `fill(color)` | Fill entire buffer; `0xFF` = white, `0x00` = black |
| `pixel(x, y, color)` | Set one pixel |
| `hline / vline / line` | Draw lines |
| `rect / fill_rect` | Rectangles |
| `text(s, x, y, color)` | Built-in 8×8 pixel font (ASCII only) |
| `blit(fbuf, x, y)` | Copy another FrameBuffer into this one |

`EPD_Landscape.clear()` is a shortcut for `fill(0xFF)` that also schedules
the next `display()` call to be a full refresh.

## Writer

`lib/writer.py` (Peter Hinch's micropython-font-to-py Writer class) renders
proportional/variable-size font glyphs onto any `FrameBuffer`-derived object.

### How it works

1. A `Writer` instance binds one font module to one display:

   ```python
   wri = Writer(epd, font14)
   ```

2. `Writer` stores a per-device text cursor in a class-level dict keyed by
   `id(device)`. The cursor is shared across all `Writer` instances that
   target the same display.

3. `set_textpos(device, row, col)` moves the cursor to an absolute pixel
   position (row = Y, col = X from top-left of the landscape frame).

4. `printstring(s, invert=False)` iterates over characters, looks up each
   glyph from the font module's binary data, and calls `blit()` on the
   FrameBuffer to stamp each glyph at the current cursor position.
   The cursor advances automatically after each glyph.

5. `invert=True` renders white-on-black (XOR of all glyph bits).

### Font modules

Each font module (e.g. `fonts/font14.py`) is generated by
`micropython-font-to-py` and exposes:

- `height()` — pixel height of the font
- `max_width()` — widest glyph in pixels
- `hmap()` — whether the font is horizontally mapped (Writer handles both)
- `reverse()` — bit order flag
- `monospaced()` — True for fixed-width fonts
- `min_ch() / max_ch()` — character code range
- `get_ch(char)` — returns `(glyph_bytes, height, width)` for one character

Writer calls `get_ch()` for each character and blits the glyph data into the
FrameBuffer using a temporary FrameBuffer wrapping the glyph bytes.

### HAUKI usage

`PriceDisplay` creates one `Writer` per font size at construction time:

```python
self.wri48 = Writer(epd, font48)   # current price
self.wri32 = Writer(epd, font32)   # cheapest 1h
self.wri14 = Writer(epd, font14)   # unit label, status messages
self.wri12 = Writer(epd, font12)   # cheapest 2h/4h row
```

Text is rendered by setting position then calling `printstring`:

```python
Writer.set_textpos(self.epd, row=5, col=0)
self.wri48.printstring(f"{current_price:.2f}", invert=True)
```

`invert=True` is used throughout `PriceDisplay` so all text appears as white
characters on a black background.

## Pixel colour conventions

| Value | Meaning in buffer | Displayed as |
|-------|------------------|--------------|
| `0` (bit clear) | Black | Black pixel |
| `1` (bit set) | White | White pixel |

`fill(0xFF)` sets all bits, producing an all-white display.
`fill(0x00)` clears all bits, producing an all-black display.

`invert=True` in Writer flips glyph bits, so `fill(0xFF)` (white background)
with inverted text produces white glyphs on a black glyph bounding box — which
is what HAUKI uses (dark text blocks on an otherwise white display).

## Sequence for one display update

```text
1. epd.clear()                        → buffer = all 0xFF, schedule full refresh
2. Writer.set_textpos(epd, row, col)  → move cursor
3. wri.printstring("...", invert=True)→ blit glyphs into buffer
4. epd.display(epd.buffer)            → transpose buffer, send over SPI, trigger refresh
```

`display()` receives `epd.buffer` explicitly. The buffer is the same object
the FrameBuffer was initialised with, so it always contains the latest drawing
state.

---

## What `display()` does internally

1. Selects full or fast refresh based on `_refresh_counter`.
2. Sends command `0x24` (write to display RAM).
3. Calls `_send_display_buffer(image)` which transposes the MONO_VLSB
   landscape buffer into portrait scan order and writes it to
   `_reordered_buffer`, then sends `_reordered_buffer` over SPI.
4. Sends command `0x22` + mode byte, then `0x20` (activate update).
5. Polls BUSY until the panel finishes refreshing.
